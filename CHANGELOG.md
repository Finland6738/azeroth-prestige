# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- M0.7: **the probe checks of the UI state, the restriction CVars and Hardcore** (V15, V16, V17), in `tools/probe/AzPr_Probe/` (`Checks_UiState.lua`, `Checks_Restrictions.lua`, `Checks_Hardcore.lua`); no check of the probe is a stub any more. V15 pairs the interaction show and hide events, reads the UI panels, follows flights and, with `/azpp uiwatch`, looks for a signal of boats and zeppelins, logs cinematics, movies, loading screens and deaths, and asks the calendar for the number of today's events. V16 only reads the candidate CVars, prints the `/console` commands the owner types by hand (`/azpp cvar`) and compares what the client restricts before, while and after. V17 reads the Hardcore realm flag and game rules, and at a death saves only the date and the instance type (`/azpp hardcore yes|no` tells the probe what the realm really is). `tools/check_probe.py` now expects code for every check and also forbids closing interactions or cinematics, resurrecting, calendar changes, CVar writes and console commands. How to run each check and what makes it pass: [docs/spike/README.md](docs/spike/README.md). Not yet run in the real client.
- M0.6: **the probe checks of the tracker sources** (V6-V11, V18) and **of the content levels** (`L`, risk R13), in `tools/probe/AzPr_Probe/` (`Checks_Quests.lua`, `Checks_Pvp.lua`, `Checks_Exploration.lua`, `Checks_Professions.lua`, `Checks_Commerce.lua`, `Checks_Levels.lua`). V6 logs the turn-ins with the completed flag, the quest's tags and levels, and times the list of completed quests. V7 lists the global and namespace names that mention Legacy before and after loading the Legacy UI, reads the achievement API, and watches the Legacy and achievement events (new command `/azpp legacy watch [seconds]|stop`). V8 follows the honourable-kill counter, the match events and winner, and reads the duel result from the system line; V18 reads the battleground scoreboard during the match and at its end. V9 compares the explored overlays and area ids before and after a discovery, times the position reads, and lists the flight nodes. V10 reads profession ranks, skill-ups, learned recipes, the recipe list with the window open and closed, and crafts. V11 records the Auction House, the mail invoices and completed or cancelled trades. `L` records what the client tells about the level of bosses, quests, zones and instances, and whether it changes. The probe only listens and asks; it writes counts, numeric ids, types and shapes, never the name of a player, buyer, guild or realm. `tools/check_probe.py` now expects code for these checks too and fails if the probe calls a game function that acts for the player or changes a setting. How to run each check and what makes it pass: [docs/spike/README.md](docs/spike/README.md). Not yet run in the real client.
- M0.5: **the probe checks of addon messages and encoding** (V4, V5, V14), in `tools/probe/AzPr_Probe/Checks_Messaging.lua`. V4 sends pings with pong replies, bursts and a size test (100 to 300 bytes) on `GUILD`, `PARTY`, `RAID`, `INSTANCE_CHAT`, `WHISPER` and a hidden custom channel, records every `Enum.SendAddonMessageResult`, and has the receiver acknowledge what arrived, so that throttle, silent loss, truncation and cross-faction delivery are measured; the channel is joined with `JoinTemporaryChannel`, its notices are hidden, it is removed from the chat frames and its members are counted. V5 takes snapshots of `C_ChatInfo.InChatMessagingLockdown()` and of every addon restriction in the open world, in combat, in dungeons, raids, boss encounters and battlegrounds, times the end of each lockdown against `ENCOUNTER_END`, `PLAYER_REGEN_ENABLED` and `ADDON_RESTRICTION_STATE_CHANGED`, and compares one test send per distribution with the flag. V14 round-trips two invented profiles through `C_EncodingUtil` (CBOR, JSON, every compression method and level, Base64, hex) with sizes and milliseconds, and sends an encoded profile to a second client. The trial and restricted-account flags are recorded. New commands: `/azpp ping`, `pong`, `burst`, `size`, `channel`, `lockdown`, `encsend`, `msgs`. Only the test prefix `AzPrP` and the test channel `AzPrPProbe` are used; test messages are capped per burst and per session and a burst stops by command; nothing names a player. `tools/check_probe.py` now expects code for V4, V5 and V14 too, and checks that every addon-message call of the probe uses the test prefix. How each check runs, what makes it pass and the procedure with two clients: [docs/spike/README.md](docs/spike/README.md). Not yet run in the real client.
- M0.4: **the probe checks of the badge surfaces** (V2, V3, V12, V13), in `tools/probe/AzPr_Probe/Checks_BadgeSurfaces.lua`. V2 reads the shapes of `UnitName` and `UnitGUID` of the players on nameplates, mouseover, target and unit tooltips, in and out of instances, next to `C_Secrets.ShouldUnitIdentityBeSecret`. V3 calls `C_NamePlate.GetNamePlateForUnit` with and without forbidden plates and `IsForbidden()` for friendly and enemy plates, counts the forbidden plate events, and anchors a 16 px test texture of the probe above the plates that are not forbidden (never to a protected plate in combat). V12 adds a chat message filter (`ChatFrameUtil.AddMessageEventFilter` or `ChatFrame_AddMessageEventFilter`) that reads sender, GUID and chat lockdown and puts a `|T...|t` texture in front of the lines whose sender is readable. V13 adds a line to unit tooltips through `TooltipDataProcessor.AddTooltipPostCall` (or `OnTooltipSetUnit`) and a harmless entry to the unit menus through `Menu.ModifyMenu`. Blocked and forbidden actions are attributed to the surface used just before them. The new command `/azpp surfaces [plates|tooltip|menu|chat|all on|off]` switches each surface off and on. Nothing names a player. `tools/check_probe.py` now expects code for V1, V2, V3, V12, V13 and V19-V21. How each check runs and what makes it pass: [docs/spike/README.md](docs/spike/README.md). Not yet run in the real client.
- M0.3: **the probe checks of encounters, group levels and auras** (V1, V19, V20, V21), in `tools/probe/AzPr_Probe/Checks_Encounters.lua` and `Checks_AntiBoost.lua`. V1 logs `ENCOUNTER_START`, `ENCOUNTER_END` and `BOSS_KILL` field by field with `issecretvalue`, the AFK and connection state of the group at the end of a pull, encounters across a loading screen, and the fallback sources (raid locks, saved instances, loot, system messages, as counts). V19 reads `UnitLevel` of the group members (near, far, offline) and of hostile players (`-1`), and times `GROUP_ROSTER_UPDATE` and `UNIT_LEVEL`. V20 reads `sourceUnit` of the auras on the player, in and out of combat, with the `C_Secrets` predictions. V21 compares `nameplateNtarget` and `targettarget` with `UnitIsUnit` and measures the cost of a plate scan; the new command `/azpp assist [seconds|stop]` scans at 2 Hz during a fight. Counters are kept in `AzPr_ProbeDB.stats`; nothing names a player. `tools/check_probe.py` now also checks the load order and that exactly V1, V19, V20 and V21 have their code. How each check runs and what makes it pass: [docs/spike/README.md](docs/spike/README.md). Not yet run in the real client.
- M0.2: **the probe skeleton** `AzPr_Probe` in `tools/probe/` (adapted from Azeroth Accord, never distributed): TOC for Interface 16001, the registry of the checks V1-V21 and `L` (stubs until M0.3-M0.7), the commands `/azpp list|run <id>|export|reset|help`, records in `AzPr_ProbeDB`, an export frame with every result and log as text, helpers for safe calls, secret values, shapes and contexts, and the log of blocked and forbidden actions. `tools/install_probe.py` copies it into the AddOns folder of `tools/local.ini`; `tools/check_probe.py`, run by `check_docs.py`, checks its TOC and registry. How to install it: [docs/spike/README.md](docs/spike/README.md). Not yet loaded in the real client.
- M0.1: **the probe specification** ([docs/spike/README.md](docs/spike/README.md)). For each check V1-V21 of [SPEC-01 §3.3](docs/specs/SPEC-01-platform-architecture.md), and for the content levels of risk R13: the exact calls and events, checked against the WoW Forever API dump (build 70170) with the names it does not list marked; where to run it (open world, combat, dungeon, boss, raid, battleground, two clients, Hardcore); the go and revise criteria; the specs and ADRs each outcome changes. The checks are grouped by the probe areas of steps M0.3-M0.7; the file also gives the probe's safety rules, the commands `/azpp list|run <id>|export|reset` and the record format `{id, result, details, build, time}`. SPEC-01 §3.3 links to it. No probe code yet (step M0.2).
